Descripción detallada

Integración de la cola de la selección múltiple con un Redis real (el servicio cache de contenedores/compose.yaml) y un grafo pequeño de dos ramas armado en código, de modo que la cola SÍ queda con una recomendación pendiente (cosa que el grafo de ictericia no muestra). 

inicio --inicia_navegacion--> q1 (selección múltiple)
  q1 --A--> qa (peso 3) --SI--> ra (recomendación)
                         --NO--> urg (urgencia)
  q1 --B--> qb (peso 2) --SI--> rb (recomendación)

Cada paso se guarda y se vuelve a leer con una instancia NUEVA de RepositorioSesionRedis, como tras un reinicio del backend, y se comprueba que la cola, la ruta, las recomendaciones y la foto para retroceder sobreviven a la ida y vuelta por Redis. No necesita Spring ni la base de datos. Si Redis no responde (sin contenedores) las pruebas se saltan. Host y puerto se pueden cambiar con -Dsignbb.test.redis.host y -Dsignbb.test.redis.port.
