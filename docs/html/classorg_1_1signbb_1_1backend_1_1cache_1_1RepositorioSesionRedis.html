Descripción detallada

Almacén de sesiones en Redis (perfil docker), según el documento de diseño: las sesiones temporales de los padres viven en la caché para que una consulta en curso sobreviva reinicios del backend y pueda compartirse entre instancias.

Se persiste el estado reconstruible (respuestas acumuladas + referencias por id, ver SesionJson) y el ResultadoPaso se reconstruye al cargar resolviendo esas referencias contra la versión del contenido clínico con la que empezó el recorrido (ContextoClinico#grafoDe). Si Redis no está disponible, falla con CacheNoDisponibleException (503): degradar a memoria crearía inconsistencias entre sesiones que aparecen y desaparecen.

MODIFICADO (CU10/CU11): implementa existe(String) y eliminar(String) con el mismo manejo de Redis caído (503).
