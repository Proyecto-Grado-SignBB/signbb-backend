Pruebas del sistema

Esta sección reúne la documentación de la suite de pruebas del backend (Spring Boot 4.1.1, Java 25). Cubre los TADs clínicos, el motor de navegación, el motor de reglas, la autoría (lienzo, reglas y revisión), la captura de observaciones y la seguridad (cuentas, roles y JWT).

Cómo ejecutarlas

Desde el directorio backend: 

./mvnw test              # compila y ejecuta la suite completa
./mvnw verify            # build completo, igual que en CI (GitHub Actions)
./mvnw -Dtest=Clase test # una sola clase
./mvnw -Dtest=Clase#metodo test

Las pruebas unitarias son JUnit 5 puro y, cuando hace falta simular colaboradores, Mockito (5.x, con el inline mock maker, de modo que también se pueden simular clases final). No necesitan Spring, PostgreSQL ni Redis.

Las pruebas de integración usan @SpringBootTest o servicios reales (PostgreSQL y Redis de contenedores/compose.yaml); el CI los levanta como servicios efímeros (signbb-backend/.github/workflows/build.yml).

AutoriaIntegracionTest está temporalmente deshabilitada con @Disabled mientras se revisa la suite unitaria por separado; sigue formando parte de la documentación y se puede volver a activar quitando la anotación.

Tipos de prueba

  • Unitarias (JUnit 5 ± Mockito): no arrancan el contexto de Spring ni usan PostgreSQL/Redis reales. Incluyen las pruebas de TADs, servicios con colaboradores simulados, controladores con MockMvc en modo standaloneSetup, el validador de Jakarta y la lectura de JSON del classpath. Son la mayoría y corren en local sin contenedores.
  • **Integración (@SpringBootTest o servicios reales):** arrancan la aplicación completa o hablan con PostgreSQL/Redis de verdad. Verifican persistencia (jsonb), cache (Redis), la cadena de seguridad y el recorrido de punta a punta. Se ejecutan en ./mvnw verify.

cache/ColaSeleccionMultipleRedisIntegracionTest no usa Spring, pero sí un Redis real: se clasifica como integración y se salta sola si Redis no responde.

Enfoque

Desde el 31-oct-2026 la suite prioriza el comportamiento esperado de los casos de uso y requerimientos. Se conserva un flujo representativo por CU y un caso por cada camino alternativo documentado en el SRS; no se persigue cubrir todos los bordes técnicos ni combinaciones internas.

Resultados

La ejecución local del 31-oct-2026 sobre develop corre 364 pruebas: 362 pasan y 2 se omiten (AutoriaIntegracionTest, deshabilitada). El CI ejecuta ./mvnw -B verify con PostgreSQL y Redis como servicios.

Cobertura

El backend usa JaCoCo. El informe se genera en cada test: 

./mvnw test
# abrir target/site/jacoco/index.html

En la corrida del 31-oct-2026 el informe marca 75,2 % de líneas y 74,6 % de instrucciones. Incluye desglose por paquete y por clase.

Para el frontend, Angular genera la cobertura con el flag --code-coverage: 

npx ng test --watch=false --code-coverage
# abrir coverage/ui-consulta/index.html, coverage/ui-autoria/index.html
# o coverage/ui-compartida/index.html

Nota: para leer reportes frescos, ejecutar ./mvnw clean antes: target/surefire-reports puede conservar reportes de clases que ya no existen.
