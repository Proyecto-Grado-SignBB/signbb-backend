Pruebas del sistema

Esta sección reúne la documentación de la suite de pruebas del backend (Spring Boot 4.1.1, Java 25). Cubre los TADs clínicos, el motor de navegación, el motor de reglas, la autoría (lienzo, reglas y revisión), la captura de observaciones y la seguridad (cuentas, roles y JWT).

Cómo ejecutarlas

Desde el directorio backend: 

./mvnw test              # compila y ejecuta la suite completa
./mvnw verify            # build completo, igual que en CI (GitHub Actions)
./mvnw -Dtest=Clase test # una sola clase
./mvnw -Dtest=Clase#metodo test

Las pruebas unitarias son JUnit 5 puro y, cuando hace falta simular colaboradores, Mockito (5.x, con el inline mock maker, de modo que también se pueden simular clases final). No necesitan Spring, PostgreSQL ni Redis.

Las pruebas de integración usan @SpringBootTest y requieren PostgreSQL y Redis arriba (contenedores/compose.yaml); el CI los levanta como servicios efímeros (signbb-backend/.github/workflows/build.yml).

Tipos de prueba

  • Unitarias (JUnit 5 ± Mockito): no arrancan el contexto de Spring. Son la mayoría y corren en local sin contenedores.
  • **Integración (@SpringBootTest):** arrancan la aplicación completa y verifican persistencia (jsonb), cache (Redis) y el recorrido de punta a punta. Se ejecutan en ./mvnw verify.

Pruebas de integración de la raíz

En backend/src/test/java/org/signbb/backend/ viven las pruebas que arrancan el contexto completo:

  • BackendApplicationTests — smoke test: el contexto de la aplicación carga. Con ddl-auto=validate, además comprueba que las migraciones de Flyway dejan el esquema que esperan las entidades.
  • ArranqueCondicionalTest — la siembra (DatabaseInit), la demo de consola (DemoTriajeRunner) y el seed de demo (SeedDemoRunner) solo existen si sus banderas valen true (sin base de datos).
  • seed/SeedGraphConverterTest — los JSON de seed/demo/ se convierten a lienzo/reglas, pasan las validaciones y vuelven a compilar con el mismo contenido y pesos.
  • seed/SeedDemoServiceTest — el seed no duplica cuentas ni subgrafos cuando ya existen.
  • PersistenciaEstructuraJsonTest — ida y vuelta de los documentos JSON por la columna estructura (jsonb) y verificación de que DatabaseInit sembró el grafo raíz. Los tests que necesitan contenido navegable insertan un subgrafo de ejemplo y lo eliminan al terminar.
  • AutoriaIntegracionTest — de punta a punta: armar un subgrafo con el servicio, aprobarlo (publicarlo) y recorrerlo como la cuidadora (ver Pruebas del módulo de autoría).
  • seguridad/ReglasAccesoIntegracionTest — la cadena de filtros real: 401 sin token, 403 por rol y 404 al recorrido de otro padre (ver Pruebas del módulo de seguridad).
  • CacheRedisIntegracionTest — cache-aside con Redis real; se salta sola si el servicio cache no responde (ver Pruebas del cache).

Resultados en CI

El workflow build corre ./mvnw -B verify con PostgreSQL y Redis como servicios. Las corridas y los conteos por clase se detallan en las páginas de cada módulo. En la rama mejoras-rondas-3-4 (23-oct-2026) corren 645 pruebas, sin fallos.

Nota: para leer reportes frescos, ejecutar ./mvnw clean antes: target/surefire-reports puede conservar reportes de clases que ya no existen.
