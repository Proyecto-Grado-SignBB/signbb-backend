Descripción detallada

Resuelve el contenido clínico (grafo y base de reglas) con patrón cache-aside: Redis como copia caliente y la base de datos relacional como fuente de verdad, según el documento de diseño.

El classpath NO participa del runtime: los JSON de ejemplo son solo la semilla de DatabaseInit. Si Redis no responde se degrada a la base de datos (Redis nunca es dependencia dura del arranque ni de la consulta); si la base no tiene contenido, falla con un error explícito.

La base de datos guarda cada grafo por separado (el raíz del sistema y un subgrafo por médico) y cada base de reglas con su grafoId. Este resolvedor los compone con CompositorGrafoClinico y cachea el resultado plano, que es lo único que ven ContextoClinico y el motor.
